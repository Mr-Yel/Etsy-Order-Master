## 需求分析：订单图片导出弹窗支持「编辑 SKU」并按编辑后的 SKU 导出
- 目标文件：`components/OrderImageExportModal.vue`（content 注入的「订单图片导出」弹窗）。
- 现状数据流：`row.sku` 取自 `transaction.product.product_identifier`；ZIP 目录/文件名走 `normalizeSku(row.sku)`（`DG…D XH` 或两横杠中间提取），而同步共享盘的 `ordersJson` 走 **raw** `row.sku` —— 已存在"原始值 vs 归一化值"不一致。
- 方案要点：新增 `row.skuOverride` + `getExportSku(row)` 统一取值出口；所有消费点（`hasSku`/selectable、`selectedSkuCount`、ZIP 目录与文件名、ordersJson）改走统一出口；UI 在 Order ID 列加可编辑 SKU 输入框；提交前映射 rows 再传给 `buildEtsyArtworkPackageOrdersJson`（.mjs 无需改）。
- 状态：**已落地实现**（用户确认方案后编码完成）。

## 实现：OrderImageExportModal.vue SKU 行内编辑
- 交互（用户拍板）：展示态 = SKU 文本 + 铅笔图标；点铅笔 → 变 input + ✓（确认）/ ×（放弃）；Enter = 确认，Esc / 点 × = 放弃；**失焦不保存**（保持编辑态，不误改）。
- 新增状态：`row.skuOverride: string | null`（覆盖值）、`editingRowKey`（当前编辑行，同一时刻仅一行）、`draftSku`（编辑期临时值）、`vAutoFocus` 自定义指令（进入编辑自动 focus + select）。
- 取值规则统一出口 `getExportSku(row)` = `skuOverride?.trim() || normalizeSku(row.sku)`，覆盖：界面展示、`selectedSkuCount`、ZIP 目录名与商品图文件名、同步硬盘的 ordersJson。
- `hasSku(row)` 改为 `override 有值 || 原 sku 非空`；确认保存后若变为空 SKU 会自动从 `selected` 移除。
- 确认保存时 trim；trim 后为空 → `skuOverride = null` 回退原值；trim 后等于 `normalizeSku(原值)` 也不落覆盖值（避免无意义覆盖）。
- 顺带修掉既有隐患：ZIP 目录用归一化 SKU、ordersJson 用 raw SKU 的不一致 —— syncArtworkPackage 改为先 `map` 成 `{orderId, sku: getExportSku(row)}` 再传给 `buildEtsyArtworkPackageOrdersJson`（该 .mjs 无需改）。
- 样式：`.sku-row / .sku-text(省略号) / .sku-edit-btn / .sku-icon-btn(confirm/cancel) / .sku-edit-input`。
- 校验：`vue-tsc --noEmit` 仅剩 `lib/kst-proxy-*` 既有报错；`wxt build` 通过（5.8s）。
- 注意：换订单状态/数量会 `fetchOrders` 重建 rows，编辑**不保留**（尚未做持久化，用户未要求）。

## 需求讨论：订单图片导出列表按订单分组展示（仅方案，未改代码）
- 痛点：`buildRows()` 把 `order.transactions` flatMap 平铺，同订单多件商品拆成多行、Order ID 重复，用户只能靠肉眼比对订单号识别分组。
- 已给出 3 个纯展示层方案（导出逻辑不动）：
  - **A 表格内加「订单分组头行」**（推荐）：分组头 `<tr><td colspan>` 浅蓝底 #E6F1FB + 左 3px #378ADD 竖条，放 订单号 / 共 N 件 / `order_date` / 买家名(`fulfillment.to_address.name`) / 已选 M of N / 整单勾选 checkbox；子行只留「第 N 项 + SKU」，组间 12px 间距；可加折叠。
  - **B 订单卡片**：每单一张卡片，分组最彻底但丢列对齐（变体/备注不再跨订单对齐），长列表滚动体验差。
  - **C rowspan 合并 Order ID 列**：改动最小，但悬浮高亮/斑马纹/折叠/无 SKU 置灰都难处理，列宽被压，不推荐。
- 方案 A 实现要点（待用户拍板）：`buildRows` 不用改；新增 `groups` computed 按 orderId 聚合（orderList 本身连续，成本低）；模板 tbody 改双层循环；选择逻辑 `selected: Set<rowKey>` 不变，加组级 checked/indeterminate + 整单全选；折叠态 `collapsedOrders: Set<number>` 可选。
- 待确认的既有隐患：ZIP 文件夹名 = `getExportSku(row)`，商品图按 SKU 去重（`productImageSkuSet`）；同订单内两件商品解析出同一 SKU 时会落进同一文件夹（附件/备注靠 `orderId_transactionIndex` 区分，商品图只剩一张）。已向用户提出，是否为预期行为待答。
- 状态：**等用户选方案，未动代码**。

## 实现：OrderImageExportModal.vue 按订单分组展示（方案 A，已落地）
- 用户选定方案 A。改动全部在 `components/OrderImageExportModal.vue` 展示层，**导出逻辑（ZIP/SKU 目录/附件/备注 txt/同步图包）零改动**。
- 新增 `OrderImageExportGroup` 类型 + `groups` computed：按 `orderId` 聚合 `rows`（订单行天然连续，一次遍历），同时算 `selectableCount`（有 SKU 的行数）。
- `OrderImageExportRow` 新增 `orderDate`（`EtsyOrder.order_date`，Unix 秒）与 `buyerUsername`；`buildRows(orderList, buyers)` 增加 `buyers` 入参，内部建 `buyer_id → username` 映射；`fetchOrders` 改为解构 `{ orders, buyers }`。
- 组级交互：`getGroupSelectedCount` / `isGroupAllSelected` / `getGroupSkuCount` / `toggleGroup`（整单全选/全不选，只动有 SKU 的行）/ `isGroupCollapsed` / `toggleGroupCollapse`；`collapsedOrders: ref<Set<number>>` 默认全展开，切换订单状态时**不重置**（切回来仍保留折叠态）。
- `formatOrderDate`：`order_date` 按 **UTC** 格式化为 `MM/DD/YY HH:mm`（遵循 `etsy-order-api-fields-mapping.md` 中「Sale Date 按 UTC 计算避免时区偏移」的既有约定），hover 有 `下单时间（UTC）` 提示。
- 模板：`tbody` 改 `<template v-for="group in groups">` 双层结构 → 组头行 `colspan=6`（浅蓝 `#E6F1FB` + 左 3px `#378ADD`，含折叠箭头、整单勾选、订单号、共 N 件、UTC 时间、买家 username、已选 M/N、该订单 SKU 数、无 SKU 提示）；子行删掉重复的订单号，只留「第 N 项」；表头 `Order ID` → `项目 / SKU`；末行加 `group-last-row` 分隔线；新增空列表 `empty-state`。
- 样式全部新增在文件末尾「订单分组」区块。
- 校验：`vue-tsc --noEmit` 仅剩 `lib/kst-proxy-*` 既有报错；`wxt build` 通过（5.9s）。
- 额外产出：`.workbuddy/preview/order-image-export-grouping.html`（静态可交互预览：折叠/整单勾选/半选态/备注保留），用于真机加载前先看效果。
- 仍待用户答复：ZIP 文件夹名 = SKU 且商品图按 SKU 去重，同订单内两件商品同 SKU 会合并进同一文件夹（商品图只剩一张）——是否按预期保留。
